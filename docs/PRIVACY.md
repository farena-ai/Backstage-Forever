# Privacy and local data

Backstage Forever has no project-operated backend, telemetry or autonomous paid background inference. Profiles and provider preferences live in Electron's per-user `userData` directory on this Windows account (normally under `%APPDATA%` using the packaged app name). Profiles include character details, notes and goals and are readable local JSON. They are not encrypted notebooks. Protect the Windows account and any backups.

API keys are handled in the main process only and encrypted with Electron safeStorage in a separate local credentials file. They are not returned to the renderer, written into profile state, or included in app exports. Secure storage is required; there is no plaintext fallback. OS-backed storage does not protect an unlocked account from every malicious program.

AI sends the prompt you explicitly submit to your selected provider. **Use my active character is enabled by default**, as requested for player alignment. Its checkbox provides a persistent opt-out and a visible preview. Automatic context is limited to public name, realm, class, level, race, faction, location, snapshot timestamp, available XP progress, up to 10 observed quests with up to 3 objectives each, their actual public-API destinations when available, and up to 10 recent observed turn-ins plus an optional completed-count. Strings are bounded to 200 characters. The preview shows this approved payload. A completed-count is not a historical quest-name database; full historical completed IDs are excluded. Raw GUIDs, account identifiers, local paths, notes and goals are excluded. A secret pasted into your prompt still leaves the computer. Local Ollama requests stay on a loopback HTTP endpoint and can work offline with a locally running model. Ollama Cloud is a separate connection using its own encrypted key, Bearer authentication and native chat at fixed `https://ollama.com`; cloud requests leave this computer. Other cloud requests go to fixed HTTPS provider endpoints. There is no automatic cloud fallback. Provider retention and billing policies apply to data they receive.

Chats are memory-only and disappear when the app closes; they are not included in backups. Exported backups contain readable profiles, notes, goals and preferences, never API keys. Keep backups private. Imported files are validated data; the app does not execute their contents.

Use Delete Key to remove one locally stored credential. Use the app's reset/delete-data control and confirm the native dialog to clear app data and stored keys. Delete exported backups separately. For an exposed key, revoke it at the provider, not just locally. To remove provider-held data, use that provider's controls. Uninstallation may retain per-user data; reset first when handing the computer to someone else. No secure disk erasure guarantee is made.

## Local guidance preferences and preparation

The Forever reference downloads whole-build public datasets from the fixed Efficient Games GitHub repository. GitHub receives normal connection information such as IP address. Requests do not include character names, active or completed quest IDs, account identifiers, notes, goals or AI credentials. Automatic reference checks can be disabled; manual refresh remains available. The bundled pack works offline. Downloaded references are validated data, never executable addon code. [Reference data details](FOREVER-DATA.md) explain the build and coverage limits.

When a supported complete public read is available, the addon can save up to 20,000 completed quest IDs locally to distinguish finished chain steps. These IDs are included in private profile backups and excluded from automatic AI context. Absence from an incomplete or unavailable history is not proof a quest is unfinished. An explicitly submitted question may include only a bounded selection of relevant compatible reference facts and chain statuses when character sharing is enabled; the preview uses the same approved context helper. Local reference search, downloads and planning never invoke an AI provider.

The local planner uses saved quest observations and runs without any AI provider request. Session length and quest focus are saved per character in the desktop renderer's local preference storage. They are not API credentials and are not part of character JSON backups. The app reset clears the planner preference namespace.

Optional preparation snapshots contain bounded equipped-item IDs/metadata and carried-bag free/total counts. They do not include a full inventory, bank, mail, money or account data. They remain in local profile backups and are excluded from automatic provider context. Missing client APIs leave the corresponding fields unavailable.

Explain my plan places bounded public quest details in the visible prompt for review. Like any prompt you explicitly send, that text goes to the selected provider even if automatic character context is turned off. It never includes private journal notes, goals, account identifiers or local paths automatically.

## Optional game connection

Game Connection installs or updates only this app's addon files in your selected client. The guarded addon records public character, quest/objective, XP and bounded recent-turn-in snapshots using normal SavedVariables. Recent history stores at most 25 observed turn-ins. A public completed-count is accepted only after a bounded complete read of at most 20,000 entries; unavailable/restricted APIs mean unknown, not fabricated progress. Setup searches bounded common C–Z drive locations and registry entries without recursively scanning drives, then offers a folder picker. It automatically prepares/verifies and repairs only its three owned addon files, preserving unrelated files. The desktop reads its export every five seconds while open; it does not execute imported Lua. WoW writes to disk only on UI reload or logout. **Levelled up or changed areas? Type `/reload` in WoW to refresh your companion.** No forced reload, memory inspection, network addon bridge or gameplay automation is provided.

Only characters visited with the addon enabled are known. The newest account export is a saved snapshot, not an account API or continuous live feed. Imports retain private notes/goals and unrelated manual profiles. Follow last played character defaults on; deliberate manual selection pauses it until the checkbox is restored. Disconnect stops imports and retains profiles. Machine-specific folder settings are separate from profile backups. Backups include imported character/source metadata; keep them private.

Model catalogs refresh on startup, connection opening, sign-in, save and manual refresh. These are metadata requests, not inference entitlement probes. ChatGPT's authenticated account catalog controls model visibility; provider API catalogs and Claude CLI initialization are not guarantees of plan entitlement. Catalog failures preserve your selection; no silent paid fallback occurs. Local off-topic gating and the shared WoW specialist policy do not form a perfect semantic classifier. The app has no companion code-execution or game-control tools.

## Automatic saves

Provider/model choices save immediately; text fields, notes and API keys save when focus leaves the field. Unsaved drafts stay in interface memory until saved. API keys use the same encrypted storage and are cleared from visible drafts after successful saving. Save failures remain visible and retryable. Nothing about saving or opening the dashboard submits an AI question.

## Subscription authentication

Subscription mode is explicitly selected separately from API mode. A ChatGPT subscription does not provide API billing credit; API charges and subscription limits are separate. ChatGPT opens an official browser consent flow and keeps app-owned tokens in main-process encrypted storage. Browser cookies are never read or imported. The preview saves one ChatGPT registration/account per installation; reset app data to switch accounts, exporting profiles first if you want to keep them. Backups include only the authentication preference, not credentials.

Claude subscription requests run the unmodified, separately installed official Claude Code executable. Its official login manages credentials inside app-private `claude-subscription` and `claude-home` directories under app userData; the app does not extract or replay its tokens, and it does not silently reuse your general Claude Code login. These credentials are managed by the official tool, not encrypted by the app's API-key safeStorage file. Protect the Windows account and do not copy these directories. Sign-out targets this private login; reset cancels pending operations and removes the app-owned CLI directories, leaving your unrelated global CLI profile alone.

Each Claude request uses an empty temporary working directory, stdin prompt, no shell, no builtin tools, empty strict MCP configuration, disabled customizations/slash commands and no session persistence. Environment API keys, OAuth token overrides and routing variables are removed so subscription mode does not deliberately fall back to API charging. Managed administrator policy can still affect official CLI behavior; this is not an OS-level sandbox. No live sign-in or paid inference was performed by the fixture tests.

Use each provider's official account controls for revocation, retained data and subscription usage. The reset control cannot erase data already held by the provider. Grok subscription mode is unavailable in this preview. Official OAuth exists, but its isolated inference adapter and credential lifecycle are deferred roadmap work.


## Update connections

Installed Windows builds contact GitHub’s public release service after startup and every six hours while open when automatic updates are enabled. GitHub receives normal connection information such as IP address; no profiles, notes, prompts, provider credentials or game data accompany those requests. Authenticated newer releases download to the app-owned cache and install on exit by default. Updates exposes opt-out, timing and manual checks. This preview accepts authenticated published preview and stable releases. Source builds never automatically check or execute installers. Reset cancels work, deletes cache and turns automatic checks off until re-enabled. Update preferences are separate from exported character backups. See UPDATES.md.
