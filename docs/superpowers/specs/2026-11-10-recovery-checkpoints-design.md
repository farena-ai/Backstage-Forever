# Automatic local recovery checkpoints

Binding umbrella: 2026-11-10-resilience-guidance-series.md. Build after Support diagnostics passes independent review. Use one focused core manager plus Store integration, trusted IPC and a companion recovery panel in existing Field Guide. No new route/service/dependency. No actual player files during development; synthetic fixtures only. Preserve version/public release and hold1.0.

## Automatic protection and bounds

Automatic local protection defaults on in a machine-local recovery preference file, separate from exported profiles. Capture only validated ordinary profile-backup content: profiles, notes/goals, journeys and preferences; strip saved conversation memory entirely and never read/copy credential/auth files. No transcript/audio. Local copies are private readable data, not encrypted notebooks or portable party files.

Keep at most3 managed checkpoint envelopes, each <=64MiB and combined <=128MiB. Validate schema, IDs, timestamp, bounded payload, SHA256 and current validateState before use. SHA detects damage, not authenticity; all local files remain untrusted. No narrative/free-form metadata. Strict generated UUID filenames in one app-owned recovery directory, bounded enumeration/read, regular files only, no child junction/symlink or hardlink traversal. Resolve legitimate data-root/8.3 aliases canonically; preserve unrelated sentinel files. Atomic writes use unique temporary files. Never execute checkpoint content.

Capture an existing nonempty journal after full successful startup; capture changed validated successful saves at most once/15min; capture changed current journal on ordinary app close; support deliberate Create point now. No scheduled job or extra polling timer. Deduplicate identical payloads. No constructor-side capture before startup succeeds. Automatic-off stops new automatic points but retains history until Clear history; manual creation remains deliberate. Ordinary saves still succeed if automatic capture fails, with a fixed visible unavailable/limit status. Explicit oversized/manual safety operations fail with useful fixed errors; never trim journal content to make a checkpoint.

Before confirmed external import, protect the current journal when automatic protection is enabled; inability to make that safety copy aborts replacement. When automatic protection is off the existing explicit import confirmation remains authoritative and must disclose no automatic safety copy. Before confirmed checkpoint restore, create a deliberate current-journal safety point even if automatic protection is off; disclose this in confirmation. Read/validate selected payload before rotation can evict it. No silent replacement.

## Restore, privacy and startup

List only bounded metadata (ID/date/reason/bytes/profile and journey counts). Preview returns an identity/hash token; native confirmation defaults Cancel and explains journal replacement, memory clearing, retained credentials and game disconnection. Recheck token/file hash and current operation epoch after dialog. Restore shares import-like main lifecycle: invalidate AI/voice/memory/report work, clear catalog context, disconnect observation, retire stale game callbacks, then atomic Store replacement with memories empty. Ordinary stale form saves cannot reattach pre-restore source state or completion evidence. No automatic game refresh/reload/movement.

Clear history has an explicit confirmation; automatic protection remains in its chosen state and can protect future saves. Explicit character deletion through ordinary saves clears ALL managed checkpoints and preserved damaged originals before committing deletion; failure to clear aborts deletion. State replacement by an explicit import/restore is a distinct operation, not this deletion rule. Update the character-delete confirmation/help accordingly. Delete all local data clears every managed recovery file and resets its preferences without creating an old-state checkpoint; preserve unrelated files. Explicit saved-memory removal/clear also deletes managed damaged originals before committing memory deletion, including Clear when the active group is already empty; refuse deletion if that purge fails. Ordinary memory saves do not silently erase originals. Normal external import clears older damaged originals consistently with its memory-clearing promise; a startup restore may deliberately preserve its newly damaged original with the explicit disclosure below. Memory-free ordinary checkpoints need not be removed for memory deletion.

At startup, distinguish Store journal parse/validation/read failure from credential failure and unrelated initialization errors with a narrow typed error. Offer Restore newest valid checkpoint only for journal failure and only when a valid point exists. Default remains Quit; Open folder still works. Before overwriting damaged state, preserve its exact regular-file bytes in one managed damaged-original file (<=64MiB; refuse safe restore if preservation cannot complete), then atomically restore validated backup with memory empty. The damaged original can contain memory/private text; disclose its local retention and remove it with Clear history/character deletion/reset. Credentials remain untouched. Recheck file identity/hash between choice and write. The player explicitly chooses Restore and restart; restart failure gets a fixed manual-restart message and clean quit. Never auto-restore or claim all startup faults are corrupt journals. Credential/unrelated failures retain existing neutral recovery dialog with no restore offer. Manager/list construction must not create files in failed startup without an explicit restore.

## User flow and contracts

store.recoveryStatus() -> {phase,automatic,count,latestAt}, fixed enums and validated timestamp only; diagnostics may include phase/automatic/count but no IDs/paths/text. Store accepts an injected manager/clock for tests without breaking existing constructor calls. Core manager owns list/create/read/clear/preference/restore-preservation safety; filesystem semantics are not duplicated in renderer. Recovery IPC owns generation/confirmation, main owns game/reset/subscription lifecycle. Strict arity/shape, no renderer path/payload. A focused recovery renderer module shows Automatic local protection, last point/count, Create now, bounded point selection/preview/Restore and Clear history, with keyboard/compact/error/loading support and retained held controls. Do not label a point current when recent saves are coalesced. Existing Support report controls/help/nav remain intact.

Self-review: raw damaged-original preservation is an explicit exception to memory-free checkpoint payloads and must remain documented/deletable. No silent restore; no timers; privacy deletion differs from deliberate replacement. Limits/failed backup cannot silently block ordinary journaling. Startup side effects are absent until a deliberate restore or successful initialization.
