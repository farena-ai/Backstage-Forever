## Architecture and data trust

Author MIT normalizer/compiler and service; keep derived factual data separately marked CC BY4.0. Bundle the initial normalized pack for offline use, plus a source lock/notice/license. Add `data/**/*` to packaged files. Each raw JSON input is bounded, validated, data-only; enforce live product/build/locale/schema/license metadata, positive safe IDs, finite0..1 coordinates, bounded text/arrays/counts. Discard/quarantine invalid optional rows and expose dropped/coverage counts; reject malformed metadata or oversized input without replacing last-good data. Literal strings are escaped, never evaluated. Fixed publisher/repository HTTPS URLs only; no URL supplied by renderer/data can become a fetch target.

Automatic reference refresh: after a valid game build is observed and game is connected, check at startup/at most once24h while app open. An opt-out cancels transfers; manual Refresh retries. Fetch only fixed public branch metadata (small branches/main endpoint), then exact40hex commit-pinned raw dataset URLs for that exact live build. Never send character names, quest IDs, GUIDs, account identifiers, notes, provider keys or paths; requests are whole-build public data only. Deduplicate requests, cap files/total bytes and retry transient failures within a bounded policy. Cache normalized packs atomically under an app-owned, safe, versioned knowledge directory. Cache validation/metadata hashes and fallback preserve last good/bundled data. No service, scheduler, recurring chat or external release watcher. Do not silently mix builds, beta/retail data or old references when the current build has no matching pack. Separate collection date from last check date.

## Knowledge interfaces

Create core knowledge normalization/validation/lookup module(s) and cache service. Exact exported signatures may be consolidated but report them before UI work:
- `knowledgeStatus()` => phase, build/bundledBuild, sourceCommit, observedThrough, lastChecked, automatic, counts, bounded message/coverage/attribution.
- `refreshKnowledge()` / `setKnowledgeAutomatic(boolean)` accept no URLs, tokens or source paths.
- `questDetails(profileId, questId)` => status (`match`,`reference`,`missing`,`conflict`), record, bounded chain nodes, givers, turnIns, objective locations, mentions, rewards, provenance and warnings. Exact quest ID plus build is mandatory; never fuzzy-match same titles. For enUS, a different active-game title is a conflict; current game wins. For other locales label English reference names instead of calling translation a hotfix conflict. Missing fields stay unknown. Bound chain walk at12nodes, detect cycles, show missing nodes honestly. Reverse next edges are chain links, not proven hard prerequisites.
- `searchQuests(query, profileId, {includeReferenceOnly=false})` is local-only, query <=120chars, <=30 results; prioritize active quest IDs, exact ID/title matches, then stable order. Empty query shows current/relevant quests. NPC/reward details never require a provider connection. Unknown-build/manual browsing may use the explicitly labelled bundled reference build, but does not enable automated directions or AI assertions about player eligibility.
- `buildGuidance`/brief enrich active step records with optional `knowledge` and `referenceDestination`, keeping existing actual game `destination` distinct. Actual game-provided destination takes priority. A community marker may be used only with compatible exact-ID/build evidence: observed turn-in NPC; objective index/type/required matching an unfinished game objective; or a single NPC explicitly named in a delivery objective with evidence label. NPC window positions are approximate player observations, not guaranteed exact spawns, paths or travel times. Explain the source. No route through unknown zones or assumed quest eligibility.
- `guidance.followUps` <=3 separately labelled candidates may come from direct reported next edges of positively completed quests. Require a complete known completed-ID set to assert the next quest is not already done; exclude active/completed next quests, missing/reference-only targets, incompatible known faction/level. Unknown race/class/reputation requirements remain unknown; label Check availability rather than Ready to accept. Do not add new kinds to existing turn-in/objective step cards silently.

Reward details: separate guaranteed-item rows from choices. Item names use only valid item rows; unknown names remain Item#ID. Money is listed copper, not a guaranteed scaled payout. Exact XP is not inferred from xpDifficulty; observed XP ranges may be shown only with level/source labels. No unsupported optimal gear/reward score. NPCs/objects and objective gain locations keep independent report/source/date provenance.

For active delivery objectives, literal whole-name matching against the published NPC catalog may add `mentions` from short objective evidence. Label this relationship as mentioned-in-objective, not a structured confirmed finisher. Never infer availability, completion or hard prerequisites from prose. Multiple/ambiguous mentions do not produce an automatic destination.

## Player-controlled in-game waypoint

Use the existing three owned addon files; no generated remote Lua data or extra game code. A desktop Copy game waypoint action calls a validated main-process handler selecting a sourced destination from the current profile/quest details (renderer cannot inject arbitrary coordinates). Clipboard output is bounded ASCII such as `/bf guide 1061 t 1413 0.3528 0.2786 1.60.1.70862`, with numeric quest/map/coordinates and t/o/r phase. No shell/code text, names or links.

The addon slash handler validates every argument, refuses combat/restricted/unknown APIs and build mismatch, and for t/o rechecks that the quest is in the player's log and completion phase still agrees. Reference-only r is an explicit user-requested marker, not a claim the quest is available. Feature-detect CanSetUserWaypointOnMap, UiMapPoint.CreateFromCoordinates and SetUserWaypoint, optionally super-track only when permitted; otherwise print simple coordinates. Never open maps/other panels automatically, run macros, reload, move, target, interact or fight. Invalid commands print help and do not toggle visibility. Preserve `/bf`, hide/show/status and native styling. Enable desktop command copy only after captureVersion0.6+ proves the updated addon is loaded; show a short reload instruction otherwise. Actual game data still flushes on normal reload/logout.
