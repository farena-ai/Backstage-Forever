## Binding boundaries

- No game movement, targeting, combat decisions, simulated gameplay input, automatic waypoints, purchases, mail/messages, memory reads, injection, protected-value bypass or forced reload/logout. Explicit existing waypoint action remains player-controlled.
- Native observations update outside combat and can work with the desktop closed. Desktop state/AI/Company/plans remain last-saved. No hidden live SavedVariables transport or promise to discover never-visited alts.
- Existing private notes/goals/journeys, credentials, intentional selection/follow-off, durable completion evidence, source ownership, stale queues/replies, reset/import replacement and provider API/subscription distinctions remain intact.
- No account/password/authentication-dialog automation, privacy/security setting changes or consent on behalf of the absent owner. New optional features degrade gracefully when unavailable. No surprise paid inference or new background model calls.
- All tests use synthetic temporary profiles/game folders, fake launches and local protocols. Actual game input, live microphone capture, credential/provider consent, actual installer execution and the owner's final acceptance are deferred. Read-only OS capability probes are allowed. No recurring release watcher jobs.
- Keep the update signing key and existing provider protocols. New third-party data needs a recorded license, pinned provenance, product/build/locale compatibility, bounded parsing and source labels. Never silently rebrand Classic/Era/Questie facts as verified Forever facts or copy GPL/AGPL guide code into MIT code.
- Use focused modules, existing queues and trusted IPC. Unknown data differs from known-empty data. Plans and optional memory remain local; deliberate sharing and selected AI memory are explicit and bounded. Human content is data, never instructions to execute.
