# Voice and optional memory 0.11

Owner-authorized third milestone, after 0.10 passes. Read the series design and work/series-voice-research.md for researched primary API signatures. No actual microphone, playback, account/privacy consent or paid inference in development tests. No 1.0 release. Existing typed companion, provider protocols and game boundaries remain.

## Local Windows voice

Implement focused core voice controller, trusted IPC/preload, fixed src/native/voice-helper.ps1 and voice-helper.cs, then focused renderer. Use WindowsPowerShell5.1 at the System32 Windows path, shell:false/windowsHide:true with fixed flags and verified helper path. Never interpolate text into shell arguments/code, invoke a browser speech service, change execution policy, install language packs, or open settings. A fixed C# entry point with background command reader and serialized output avoids PowerShell background event runspace errors. Microsoft installed local desktop recognizers/voices only; absent, blocked, unknown or non-Microsoft engines degrade to typed input. Enumeration never sets an audio device. Capability means installed engine, not permission or functional audio.

Choose trusted ASAR-to-owned-runtime preparation, not asarUnpack: read bundled fixed helper bytes through Node, prepare/repair only app-owned userData/runtime/voice files, atomic writes and exact readback, reject symlinks/redirected ancestors/path escapes. No renderer-controlled paths. LF attributes and exact packaged source-byte checks include both files. No subprocess receives a virtual ASAR path.

Use disposable workers, strict NDJSON on stdin/stdout with v:1, main UUID operation id and fixed commands capabilities/listen/speak/cancel; strict known event schemas. Main owns worker factory for fake-backend tests. Limit line32KiB, aggregate stdout128KiB, stderr16KiB, transcript/plain-TTS4000 characters, enumerations32 each, capability/startup8s, listen15s and silence4s, TTS60s, cancellation kill deadline1s. Reject unknown keys/types/events, mismatched IDs, malformed/oversize outputs and duplicate terminal effects; settle once, clean all listeners/timers. No transcript/raw stderr logs, audio files, SSML/URIs or automatic retry that starts audio. EOF/error/timeout disposes and exits. Safe capability enumeration may run on the real host/packaged app; recording/playback tests use fake workers only.

Expose exact narrow methods through trusted current sender/main frame/reset checks: voiceCapabilities() no args; companionContext({profileId,view}) where view ai/other invalidates operations on every navigation/context change; voiceStart({profileId,culture}) records only current ai context using enumerated culture; voiceStatus(sessionId); voiceStop(sessionId); voiceSpeak({profileId,text,voiceId}) explicit plain text; voiceCancel() no args. Status returns bounded {sessionId,phase,draft,incomplete,message}; phases idle/starting/listening/speaking/stopped/unavailable/error. Profile ID must equal the latest activeProfileId, including null only when none is selected; null permits general WoW draft/reading but not memory. Microphone startup also requires the current trusted window to be visible and focused, checked before and after asynchronous preparation/discovery, so an already blurred window cannot start late input. Focus loss advances an input-specific cancellation generation without discarding a current explicit reading or AI request. Main owns session/profile/view/epoch checks. Cancellation during preparation/probe/startup must prevent late audio attachment. Renderer destruction, navigation, profile/provider changes, import/reset/delete/clear/quit invalidate pending effects. Window blur/lost capture immediately cancels microphone input and pending input startup. It does not discard an otherwise current AI reply or cancel an explicitly requested TTS reading: those may finish while the player returns focus to the game, still bounded by their normal lifetime and context/Stop guards. No background microphone remains active. Cancel output before input. Stop/cancel cannot reactivate audio.

Renderer offers an explicit hold-to-dictate button with visible state/countdown and release/lost capture/Space or Enter release/blur/Escape stopping immediately. RecognizeAsyncStop can keep listening: use cancel/dispose and owned-process termination backstop, preserving only already emitted hypotheses as an editable incomplete draft. Never auto-send. Preserve pre-existing question text/caret and typing during capture: insert at the captured range only if that draft is unchanged; otherwise show the bounded dictated draft separately with an explicit Insert action rather than overwriting newer edits. Existing Enter sends and Shift+Enter newline remain. Explicit Read answer/Read plan and Stop use local TTS; no automatic narration. Read plan uses bounded visible public quest facts and retains saved-date/source/reference/clue qualifications in the spoken text; private goals and journals are not automatically narrated with a plan. Typed fallback always visible. Poll status only during visible active operation. Integrate shared InteractionGuard without moving root queues or blocking native controls. Update listening/countdown/status text in place while the button is held; deferring root replacement must not hide the fact that the microphone is active or replace the held node.

## Explicit per-character memory

Use optional main-owned root state memories, default[], schemaVersion remains1. Pure memory-data validation avoids root-validation cycles. Shape: <=100 groups {profileId,exchanges:[<=20 {id,createdAt,question,answer}]}; profileId must reference existing profile, groups unique, exchange UUIDs unique globally, canonical ISO time, question nonblank<=1000 and answer nonblank<=2000/no NUL. Main generates IDs/date. No automatically captured exchange or summary, notes/goals/journeys excluded. Keep ask returning its existing reply string. memoryDraft(profileId) returns the current main-owned eligible response as {profileId,responseId,question,answer}, bounded to the stored limits for explicit on-screen review; unavailable/stale context returns null. saveMemory({profileId,responseId}) stores exactly that reviewed server draft, only for the current active character/current response context; it accepts no arbitrary renderer history text. A main UUID responseId binds the draft to the request/context, consumed once or reused idempotently without duplicating an exchange. deleteMemory({profileId,id}) and clearMemory(profileId) are strict latest-state atomic actions. Public list detached. Ordinary renderer saves preserve latest main-owned memory and prune deleted profiles before root validation, including mergeUserEdits. Isolated single-profile GameSync validation temporarily supplies memories:[] only for that isolated validation view, without clearing actual root memories belonging to other profiles. Store export omits memories, validated import clears them atomically with imported state, reset clears. Old snapshots/backups normalize missing collection to empty. Imported nonempty memory validates before being discarded; unknown malformed content must not bypass validation.

Saving and sharing are separate explicit actions. Future-use selection defaults off and clears on character/provider/navigation/reset/import/delete/clear. Expose memoryPreview({profileId,prompt,memoryIds}) with selected <=5 UUIDs owned by current character, no duplicate/missing IDs, plus ask's optional memoryIds validated identically. A shared pure builder returns exactly the augmentation actually sent and selected bounded public excerpt. Combined prompt <=12000 including original question and clear untrusted-conversation delimiter; never truncate original question or silently drop selected memory. Reduce selection on budget error. Retrieve quest/public context and scope validation from original question, not memory. All API, OpenAI subscription and Claude subscription paths use the same augmentation. Memory is untrusted conversation, never verified game evidence or instructions to execute. Existing shareProfile whitelist and API/subscription distinction remain unchanged.

Use one focused main-owned companion-context.cjs controller and the single companionContext IPC, established by the memory task and reused by the voice task. It checks the latest active profile/provider, owns invalidation subscriptions and a generation; renderer context notifications are explicit navigation/profile/provider/clear events, not ordinary same-character observation polls. Every notification invalidates pending effects even if the declared view repeats (Clear chat). Main also invalidates on owned import/reset/profile deletion/provider/auth changes and renderer loss/quit, so it does not rely only on renderer notifications. Actual game-source root transitions invalidate synchronously when the root changes or clears, including empty sources before asynchronous preparation finishes; a finally-only notification leaves a stale-effect window and is insufficient. Ordinary same-root refresh/observation is not a source transition. Main-owned assistant context generation binds each request/response to current profile/provider/view plus memory mutation epoch; late replies cannot display/save/speak in a different context or recreate deleted content. Explicitly cancel display effects, do not claim a network charge was cancelled. UI memory actions use existing mutation queue/state epochs and latest committed state. Memory helper is focused and uses shared dispatch guard; no silent persistent consent flag. Privacy/export/onboarding docs describe local memory separately from deliberate per-question sharing.
