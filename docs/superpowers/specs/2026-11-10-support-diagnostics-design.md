# Support diagnostics design

Add a graphical Support & Recovery card to Field Guide, backed by focused core/renderer modules. No new navigation destination. Existing Game Connection/update failures can link there without changing the eleven main routes. The player chooses Prepare report, reviews a clearly labelled snapshot, then Copy or Save. No upload, telemetry, account request or inference. Reporting must not inspect audio or enumerate private files.

Build a fixed-schema projection, never JSON.stringify a state/status/log object and then redact it. Allowed fields: report schema/time, known app version/channel, platform/architecture, OS-backed storage availability, profile count, selected provider ID/access mode/key-present Boolean (not entitlement), bounded game/setup/addon status enums and coverage counts, reference status/build with strict shape, updater phase/known diagnostic code and semver versions, and checkpoint availability when that service exists. Unknown inputs become fixed unknown labels. No model names, character/profile/source IDs, names, realms/race/class, paths, machine/account identity, prompts, memory, notes/goals/journeys, URLs, auth metadata or free-form error/message fields. Even allowed enums must use explicit sets. Time comes from injected clock, not player data.

Main prepares one immutable {id,text} snapshot with crypto ID and five-minute lifetime. Copy/save accept only that current ID and use exactly its text. Regeneration, reset and expiry invalidate old IDs; a pending save dialog must recheck ownership before writing. Save uses native chosen .txt destination, atomic bounded UTF8, and rejects destinations inside app-owned data even via canonical aliases. No renderer-supplied path/text. Exports are deliberate, no saved report history. Preview uses escaped text, status announcements, keyboard-accessible actions and a real waiting/error state. Regional refresh must preserve held controls/draft/focus; no root refresh while a physical gesture is held. Leaving the page retires UI work; late results cannot replace another page or make obsolete actions current.

Collector reads current local state/status only, without connecting providers or refreshing public data. Subscription auth status that would spawn a CLI is not checked; configured access mode is reported separately from verified access. Existing transport errors stay out. Checkpoint fields default unavailable until the later service is integrated. Main reset clears the diagnostic snapshot before replacing local state.

Tests cover malicious canaries everywhere, exact projection/enum/size limits, no raw errors, preview/copy/export byte equality, expired/regenerated IDs, late dialog completion, path aliases, cancellation and no automatic network. Actual isolated Electron proves guide discovery, keyboard preview/copy/save through fake native surfaces, held-control retention, navigation/reset races and compact/full layout. Documentation explains scope and manual sharing. No dependency/version/provider/addon/reference changes in this subproject.

Self-review: an allowlist avoids brittle redaction, snapshot IDs avoid renderer/export mismatch, and locating the tools in existing Field Guide avoids another setup step. This does not implement log capture, file attachments or sending to support.
