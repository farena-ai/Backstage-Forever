## Structured response and final self-review

askCompanion's existing input is unchanged; local response is {text,kind:'travel',conversation,travel:{status,headline,origin,destination,options,cautions,claims,sources,coverage,choiceToken}}. claims are {text,sourceIds} selected from validated reference, never AI text. choiceToken is an opaque UUID string only for a current completed route with options; otherwise null. Options use the exact approved planner fields. No history/source-owner/private paths/keys in metadata. createTravelPlan consumes exactly {profileId,token,optionId}; token is this choiceToken, not the internal ConversationSession object token. openTravelSource consumes exactly one static source ID. The main service creates all origin markers; renderer cannot declare an AI reply trusted. Local reply and its original question remain saveable only through the existing reviewed MemoryService eligibility rules.

Self-review: dedicated pending/current trip state is bounded main-owned volatile data and uses only actual accepted USER intent, not priorAI authority. Same request serialization and explicit privacy scope apply to local answers. Source data is already independently reviewed, small and immutable; no new capture, travel optimization, route promises or external publication is introduced. Options are simple to read and remain powerful manual checklists, with all native game actions outside this feature. All required interfaces and ownership seams are defined; no unresolved user decision blocks implementation.
