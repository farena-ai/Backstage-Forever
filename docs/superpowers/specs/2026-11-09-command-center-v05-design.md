# BF 0.5 character command center

Owner requested implementation on 2026-11-09: character command center, verified quest guidance slice, final graphical polish, beginner-friendly automation. Use existing checkout, original artwork, Electron and native addon; no account service deployment or provider inference in tests.

## Chosen approach

Hybrid native addon plus desktop: gather permitted public character/quest/preparation data outside combat, preserve the validated SavedVariables boundary, automatically build deterministic guidance on import and character selection, use optional AI for player-requested explanations. Compared with AI-only plans, this supplies repeatable source-backed steps without credits; compared with building a full external database now, it ships a verified observed-quest slice without unsupported quest-chain claims.

## Scope and interfaces

1. `buildGuidance(profile,{now,minutes,focus})` in `src/core/guidance.cjs`: return `{version:1,status,headline,freshness,steps,counts,limitations}`; steps `{questId,title,kind,reason,objectives,destination?,source}`. Kind is `turn-in` or `objective`; source `{kind:'game-snapshot',observedAt,questId}`. Default minutes30, accepted15/30/60; focus balanced/nearby/turn-ins. Known turn-ins prioritized, then current zone/map and suitable reported quest level; stable ties. Limit steps by selected session length without invented time estimates. Never create quests, NPCs, coordinates, prerequisites, rewards or completion history. Expose through `buildBrief(...).guidance` and a `guidancePlan(profileId,options)` preload/IPC endpoint; AI context may include bounded evidence only with existing consent.
2. Optional `readiness` snapshot `{equipment:[{slot,itemId,name?,quality?,itemLevel?}],bags:{free,total}?}`: no item links, account data, money or full inventory. Strict bounds19 slots; item IDs positive safe integers; names<=200; quality0..8; level0..10000; bag counts0..1000. Missing APIs omit data. Update parser, state validation, profile merges, approved provider context as appropriate; local readiness excluded from cloud context by default unless explicitly permitted by existing scope. Do not silently migrate identity fields without Forever-specific proof. Add capture error state to native HUD, reporting fixed friendly messages instead of raw errors.
3. Command center: preserve Adventure navigation label but present player-centered dashboard and roster switcher with class/faction art, selected-character identity, XP, freshness, ready quests and preparation. Session15/30/60 and focus selectors autosave locally per character and rebuild plan automatically. Display 3-8 source-backed action cards, a useful empty/unavailable state, and expandable evidence. No submit/save prerequisite for guidance. `Explain my plan` prefills AI prompt and uses existing send flow; never auto-infers. Existing private notes/goals stay intact. No large repeated ready banner. Compact topbar status links Game Connection; explicit reload hint only where actionable. Roster cards expose imported/manual source and last observation, clarify another toon must be visited once.
4. Final visual pass retains original paintings and bundled fonts. Sculpted action cards, an ornate but readable section hierarchy, class/faction accents, consistent spacing and states, compact layout at1000x700, keyboard/focus/contrast, reduced-motion and hidden-window pause. No new bitmap assets or new graphics dependencies required.
5. Tests: real Lua VM with realistic multi-return APIs, missing/protected APIs and errors; guidance fixtures for current/completed objectives, unknown vs empty, source integrity, stale/manual, duplicates, stable sort and no mutation; schema/parser/merge/backup compatibility; real Electron controls, autosave per-character isolation and seven-page banner regression; packaged resources readback. Actual game validation only with observation or user action, never automated gameplay.

## Trust, delivery and constraints

Desktop freshness always means last disk save, never live. All API values and snapshots remain bounded/untrusted; no code evaluation, injection, memory reading, combat decisions or simulated gameplay. Source-backed does not mean a complete quest database. Battle.net account linking is research-only in0.5 until a registered secure native authorization route and real support can be verified; no embedded client secret. Keep AI-provider/API/subscription distinctions and encrypted credentials. No new background inference, telemetry or release watcher. Ship Windows0.5.0 through the existing signed-manifest release workflow after review/test gates; no invented live acceptance or self-upgrade claims.
