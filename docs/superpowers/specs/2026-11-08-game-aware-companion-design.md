# Game-aware companion — 0.3.0

## Owner requirements
Increase the graphical treatment; automatically ingest and refresh the player's characters/level/server/location; automatically refresh provider models based on connected access; add Ollama Cloud; specialize the companion for World of Warcraft: Forever; make advanced behavior simple for AI beginners.

## Chosen approach and constraints
Use an optional normal WoW addon plus a read-only local SavedVariables watcher. This is simpler and keeps account credentials out of the game; a Battle.net account integration adds registration/auth complexity and does not establish a realtime Forever API. Addons cannot arbitrarily write desktop files or use HTTP; snapshots reach disk on logout/UI reload. Therefore this milestone implements automatic saved-snapshot synchronization with visible age, never claims a continuously live feed, never forces reloads or reads game memory. A future read-only realtime channel requires separate verification. The local installed client reports wowf 1.60.1.70862 and Config.wtf engineSurveyPatch 16001; choose a real Interface 16001 addon with runtime API/capability guards, still distinguish loader evidence from actual in-client acceptance.

## Character sync
A beginner Game Connection screen detects likely Forever installations, offers folder selection and one-click install/update of only this app's addon. No personal path ships in source. The desktop reads only its addon's snapshots and optional character-directory names for discovery, not other addon/chat/account data. Account names, paths and GUIDs are local identifiers, never automatic AI context. Addon tracks logged-in characters with public player identity/class/level/race/faction, zone/subzone/mapId/position and timestamp, updates on relevant events outside combat, persists a bounded JSON string through SavedVariables. No input automation, combat computation, forced logout/reload, network, hidden screen pixels or protected-value bypass.

Desktop parses only a restricted Lua string assignment to the named JSON export; never eval/loadfile/execute Lua. Validate schema/limits and reject partial/malicious files. Scan bounded directory depth/entries, refuse symlinks/path escape, debounce changes/poll while app open, preserve last good snapshot on parse errors. Merge by stable app-local identity; preserve user notes/goals and manual profiles. Read-only imported fields carry optional source metadata, updatedAt and location. Prefer the latest snapshot's active character unless the user intentionally chooses another. Snapshot age is explicit in UI/context; never claim online/combat state from disk. Disconnect/reset cancels scans and prevents late merges. Exported backups include profiles but not machine-specific connection settings. Installation replaces only owned addon files, never deletes others or alters game settings. Installation while game runs explains restart/reload necessity rather than automating it.

## Provider discovery and Ollama Cloud
Main-only model discovery uses the selected provider and auth mode. ChatGPT subscription: authenticated GET /v1/models, models array, visibility=list, slug/display_name, server order. API providers: provider model endpoints, bounded pagination/size, safe errors, no inference/billing probe. Ollama local: /api/tags loopback; Ollama Cloud: fixed https://ollama.com/api/tags and /api/chat with its own API key, never silently substitutes local/cloud. Claude subscription uses supported official CLI/SDK model catalog without a user inference request; if catalog is not entitlement proof, label that honestly. No hardcoded 'your plan includes' list or imported API credential substitution. Discovery failures preserve the selected model and expose retry; never silently change models/providers/billing mode. Cache by provider/auth/account generation; invalidate on login/logout/key edits/reset. Refresh on startup for already configured connections, successful sign-in/save, provider screen opening and user refresh; throttle repeated refreshes and prevent stale asynchronous results replacing a newer connection. Model picker has friendly labels, status and an advanced manual entry escape hatch, not a mandatory exact-ID lesson.

## Specialist companion
One shared policy explicitly identifies World of Warcraft: Forever, never asks which game Forever means, assumes all screen questions are about that game, uses the selected character context/zone/level when approved, and differentiates general WoW advice from unverified Forever specifics. Reject clear unrelated programming/general-assistant requests before provider execution; user prompts cannot enable tools, arbitrary code, game input or live combat decisions. WoW macro/addon configuration help may be discussed as supported game help, not executed. No claim that a regex or prompt perfectly enforces every semantic boundary. AI UI has task chips and a player/context preview. Current-question context excludes private notes/goals/account/GUID/path; user can opt out. Since owner explicitly requests alignment to the player, default 'Use my active character' is enabled with clear preview and retained user opt-out. Local situation/next-step cards update automatically from snapshot and are labeled planning suggestions, not a verified quest engine. No unattended paid inference or silent fallback.

## GUI/art

Use original bundled artwork, textured materials and accessible labels/focus/reduced motion. Preserve existing profiles, update controls, auth and tests. No sample records presented as real player imports. Personal local characters may be examined for validation but never committed, exported into demo screenshots or published as fixtures.

## Interfaces
Provider backend: listModels({provider,authMode,endpoint?,apiKey?,chatgpt?,claude?}) -> {models:[{id,label}],source,checkedAt,message}; ChatGPTAuth.listModels() and claude.listModels() support their own auth, main handles caching/lifecycle. Ollama Cloud provider id ollama-cloud, fixed endpoint https://ollama.com.

GameSync class({dataDir,addonDir,onSnapshot}) -> status(), discover(), connect(root), installAddon(), refresh(), disconnect(), reset(), close(). status sanitized {connected,addonInstalled,phase,message,lastSync,characterCount,clientVersion,interfaceVersion}; discover returns candidate {id,label,path} only to local UI; connect path validated and stored privately. onSnapshot({characters,activeId,observedAt}) contains validated game records; parent merges into Store and updates optional profile source {kind:'wow-addon',id,updatedAt} and location {zone,subZone,mapId,x,y}. Optional race/faction fields. New bridge gameStatus(), discoverGame(), connectGame(path?), installGameAddon(), refreshGame(), disconnectGame(); connectGame without path uses native folder dialog. Bootstrap includes gameStatus. New model bridge listModels({provider,authMode,endpoint?}) uses saved main-only credentials and sanitized results; no arbitrary cloud URL or key readback.
