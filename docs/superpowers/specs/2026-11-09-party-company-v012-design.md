# Party and Company 0.12

Final capability milestone in the authorized0.9–0.12 series, followed by the Quest Guide visual/data pass and public0.12 signed release. No1.0 until owner acceptance.

Choose deliberate local plan exchange over online party synchronization (accounts/consent/server scope) or game-chat automation (unsupported). The owner previews exactly what leaves the machine and deliberately saves/opens a JSON plan file. No messaging, network party discovery, account linking or automatic import.

## Portable public plan

New pure party.cjs owns strict schema and conversion. Portable shape exactly {format:'backstage-forever-party',version:1,title,steps}; title nonblank<=100/noASCIIcontrols, steps1..50 each exactly {text} nonblank<=300/noASCIIcontrols. UTF8<=64KiB. Unknown keys, private fields, IDs/profile/source/proof/done/observed metadata, unsupported versions, malformed JSON and duplicates of structural keys must be rejected rather than accidentally trusted. Plain imported text is inert data, never instructions/actions/HTML. Export only deliberately selected existing journey step text; start with the generic portable title Shared adventure plan rather than automatically copying a character-bearing journey title. Project only title/text, never structured private notes/goals/character identity/account identifiers, source hashes/paths, completion status or proof. User-authored step text may itself include personal wording: show every line and a clear privacy warning for owner editing/checking before file save; do not claim automatic semantic redaction of arbitrary prose. Default export template contains generic dungeon preparation checklist, not actual private notes. No attachments, URLs fetched, shell commands or game input.

partyPreview({journeyId}) produces detached bounded {title,steps} from latest current state with no automatic export. exportPartyPlan({title,steps}) uses trusted save dialog and atomic write after strict validation; importPartyPlan() uses bounded file picker/read and returns detached preview only, not mutation. commitPartyPlan({title,steps}) revalidates current snapshot, creates a single new journey with new main-owned IDs/date and manual unassigned profileId:null steps, done:false, no quest or observed fields, all-or-nothing. Existing20journey50step caps apply; readable capacity error, no partial creation or overwrite. Import dialog epoch prevents late file read after reset/import/context invalidation; cancel no mutation. No trust from filename/extension/content. All IPC exact counts/keys with existing sender/mainframe/reset checks. File dialog automation in synthetic backend uses injected safe fixtures, never real-user files.

## Dungeon preparation

Pure buildPartyBrief(state,profileId,{role}={}) returns current selected character's bounded public observed class/level/equipment/bag facts with source/time, selected role tank/healer/damage/unspecified and manual generic checklist. Role is player's choice, no inferred class eligibility or promised dungeon access, gear score, queue availability, loot/encounter scripting. Equipment unknown differs from empty; rank/inventory no imagined readiness. Default template includes plan/role agreement, known bag space, consumables check, repair check and meeting point agreement, expressed as manual checks rather than falsely observed facts. createPartyJourney({profileId,role}) deliberate current active profile ornull, atomic manual checklist using existing journeys. Optional role preference UI local percharacter; no game/source modification. No AI call or automatic actions.
