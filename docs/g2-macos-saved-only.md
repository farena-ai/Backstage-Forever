# G2: macOS saved-only and capture assessment

## Saved-only source qualification

Baseline: `3da073016f32563b2de1fe96e1f49270613f7404`. The existing Mac discovery looks for `World of Warcraft/_forever_` in system and user Applications. A custom install can be selected in Game connection. Setup validates the Forever folder, installs the addon, and imports local SavedVariables as bounded data, not executable Lua. Launch the game with the usual launcher, enable the addon, play, and log out normally. Refresh saved snapshot only reads files the game already wrote. This workflow does not need Screen Recording or the Windows game launcher/capture worker.

Closed one capability-status gap: the Windows live-link preference had been treated as usable on macOS, and an already-disabled preference could make an unsupported bridge look merely paused/off. Game connection now identifies the saved-only mode and never offers an actionable capture switch there. Unsupported writes are no-ops even through IPC; an absent preference stays absent and existing bytes survive. Windows preferences and capture defaults are unchanged.

- `node --test tests/macos-saved-only.test.cjs` verifies Mac discovery candidates, unsupported status before startup with absent/on/off preferences, zero capture spawn, preference byte preservation, and the renderer's hidden control while support is unknown or unavailable.
- `node scripts/setup-smoke.cjs --mac-saved-only` uses the real Electron main/preload/renderer with the bridge's `darwin` selector forced and a forbidden-spawn sentinel. It installs the addon into a synthetic folder, imports a synthetic save, shows the saved quest and XP, refuses capture through the real IPC, and reopens the saved journal after removing the input file. Discovery results and runtime probe are fixtures in this smoke; the separate Node tests cover candidate paths and validation. This is Windows-hosted source evidence, not execution on macOS.
- Existing setup and live-link renderer smoke passed on Windows (the live link is fed fixture frames). The targeted run passed 134/134 tests, including the existing hairline/compact/safe decoder replay. Decoder success says nothing about macOS pixel acquisition, colour, or scaling.
- This slice fixes the live-link capability control, not all related copy: the existing Questions from the Game and Live Moments settings are still present in Game connection. Neither enables capture. Platform-specific treatment of those panels and the tour is a follow-up.

## Capture verdict: candidate identified, native prototype deferred

Use a small, separately built, **non-distributed ScreenCaptureKit spike** on an authorized test Mac. Do not port the Windows worker: its screen-coordinate fallback can read desktop pixels and does not meet G2. Do not turn on Electron's capture handler or change production permission policies. [Electron's desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer) is not sufficient as the identity/consent boundary: its documented source metadata does not attest to the owning app, and the optional system picker can bypass the request handler. A window title or a valid decoded strip is not game identity.

[Apple’s ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) documents the exact-window `SCContentFilter(desktopIndependentWindow:)` and the screen-only output path. [Apple’s framework walkthrough](https://developer.apple.com/videos/play/wwdc2022/10156/) describes owner PID/bundle metadata, window identity, and frame status. That makes it the better native candidate, not a proof that any particular picker, permission transition, client identity, or package works. Prefer a single-window system picker **only if** the selected window can be bound to an independently validated owner before frame acquisition. If the target or permission cannot be established, stay saved-only; do not silently substitute another API or scope.

Proposed boundary for the spike:

1. No capability at startup. Require a fresh local Start action and explicit choice of one validated game window, plus OS authorization for that session. Bind the approved window ID to the live owning process and the vetted installed client (verify bundle identity and code-signing identity against the supported client); revalidate after each acquisition await and on target changes. Do not approve by title, path text from a renderer, or decoder success. Ambiguity, relaunch or replacement requires new consent.
2. Use only a desktop-independent window filter and video output, with no display fallback, audio/mic, overlay/input access or network path. Accept bounded complete frames only. Normalize physical-pixel coordinates, stride, channel order and colour; crop the addon strip immediately in memory and hand only bounded RGB to the existing `decodeStrip` contract. Test top-edge and corner modes without changing the wire format, thresholds or freshness rules. No pixel dumps, screenshots, recording, disk cache, or raw-frame renderer IPC.
3. Keep visible sharing status and a local Stop action; clear live state, invalidate in-flight callbacks and release native resources on denial, picker cancellation, system stop/revocation, target loss, invalid frame geometry, teardown or acquisition failure. No retry/regrant without explicit new action. Continue reading saved data independently.

### Native gates before broader enablement

| Gate | Required witness | Status |
| --- | --- | --- |
| Saved-only Mac | Test an actual unpacked Mac bundle on Apple silicon and supported Intel separately. With Screen Recording not granted: no prompt at launch/import, discover or choose a real designated test install, install addon, import a new logout save, reopen journal and verify saved/source labels. | Deferred |
| Consent and exact identity | Using a separately built disposable spike and an authorized test user, exercise deny, cancel, grant, same-title wrong window, other windows from the same app, ambiguous owner, launcher instead of game, process/window replacement, and OS stop/revoke during acquisition and while running. Prove no frame intake before both approvals or after revocation, no auto-resume, and a new action is needed to restart. If revocation is not observable/reliable for a supported OS/path, do not enable that path. | Deferred |
| Pixels and teardown | Verify valid decoder output in windowed play at 1×/Retina scale, resize, occlusion, minimize/restore and monitor changes. Verify no wrong-window samples or desktop fallback, stale/invalid samples never shown as live, and no resources/callbacks survive stop/exit. Retain only counts, latencies and enum outcomes. Repeat on each claimed OS/architecture and test the exact intended app identity/signing under macOS privacy controls. | Deferred |

No native helper, entitlement, permission change, capture IPC, package, deployment, or production rollout is included in this slice.
