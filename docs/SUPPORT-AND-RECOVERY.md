# Support and recovery

Open **Field Guide → Support & Recovery**, then choose **Prepare report**. Review the displayed snapshot before choosing **Copy report** or **Save report**. Nothing is uploaded or sent to support automatically. Share the copied text or saved `.txt` file yourself only if you want to.

The report contains fixed, bounded facts: app version/channel, operating-system platform and architecture, whether secure credential storage is available, profile count, selected provider ID and configured access mode, whether that provider has a saved key, connection/setup states and coverage counts, public reference status/build/counts, and update phase/known diagnostic code/versions. Configured subscription mode does not prove sign-in, entitlement or remaining quota. Preparing a report does not run a provider CLI, connect to a provider, refresh public data or inspect audio.

The report excludes character/profile/source identifiers and names, realm/race/class, private notes/goals/journeys, conversations and saved memory, prompts, model names, local paths, machine/account identity, URLs, credentials, sign-in metadata, logs and free-form error messages. Unknown or malformed facts appear as `unknown`; this feature does not attempt to redact arbitrary private text from a log dump.

Copy and Save use the exact main-process snapshot shown in the preview, rather than rebuilding it or accepting text/path from the page. A newly prepared report replaces the previous snapshot. Reports expire after five minutes; leaving Field Guide clears its displayed review, and Delete all local data invalidates the stored snapshot. If an action fails or the report expires, prepare and review a new one. A pending save is checked again after the native dialog, so reset, regeneration or expiry cannot write a stale snapshot.

Save uses your chosen text-file destination, with an atomic write. Destinations inside the app-owned data directory are rejected, including canonical directory aliases. No report history is kept. Files you deliberately save elsewhere and text you put on the clipboard remain under your control; reset cannot remove copies you shared.

## Automatic local protection

Open **Field Guide → Automatic local protection**. Protection defaults on without setup. A successful startup protects a nonempty valid journal; changed saves create a point at most once every 15 minutes, and ordinary app close protects remaining changes. Identical content is not copied again. There is no recovery timer, scheduled task, watcher or network service. Recent edits can be newer than the latest dated point.

Keep up to **3 permanent points, 64 MiB each, 128 MiB combined**. Rotation stages a new memory-free point, then evicts only enough old points before promotion. Rollback may briefly use more than one staging file; combined committed checkpoint and staging storage stays within 192 MiB. At least one prior usable point remains throughout production rotation. A later authorized capture validates and removes abandoned complete stages within its cleanup budget before trying again; listing and failed-startup inspection never perform cleanup. An interrupted rollback with stages above that budget refuses new points until you deliberately clear recovery history; a prior committed point remains usable. Unsafe or undeletable remnants stop new staging rather than accumulating copies. Points contain validated private profile-backup data: profiles, notes, goals, journeys and preferences. They exclude credentials and saved conversation memory. These are readable local files, not encrypted notebooks or portable party plans. The machine-local automatic choice and recovery history are excluded from exported profile backups. SHA-256 detects damage, not authenticity; local checkpoint files are always treated as untrusted data.

**Create point now** deliberately saves the current journal, including when automatic protection is off. Turning protection off retains existing points. **Refresh recovery history** retries local status after a storage problem. A failed automatic point does not prevent ordinary journal saves. Oversized journals are never trimmed: manual creation and safety-copy operations fail with a fixed size-limit message. Keep an exported backup elsewhere to protect against drive loss.

Choose a dated point, select **Preview selected point**, then **Restore selected point**. The native confirmation defaults to Cancel. Restore creates a deliberate safety point of the current journal even with automatic protection off, replaces journal/preferences, clears saved memory, keeps existing API credentials and disconnects game observation until you deliberately reconnect. It retires work for the former character/source context. Import, restore and Delete all local data refuse journal replacement if the persisted game connection cannot be removed; a disconnected live indicator alone is insufficient. If restore succeeds but recovery history or journal details cannot refresh, the restored journal remains applied and the old preview is retired. Choose **Refresh recovery history** to retry only those display reads; do not repeat restore to repair the display. If the point or journal changes while confirmation is open, preview again. External backup import protects the current journal when automatic protection is on; inability to create that safety point aborts replacement. When protection is off, the import confirmation discloses that no automatic safety copy is made.

**Clear recovery history** removes all managed points and any retained damaged original. It keeps the automatic choice; future saves can protect new changes. Character deletion clears **all** managed history and damaged originals before committing deletion, so a deleted character is not left in another character's checkpoint. A purge failure refuses deletion. **Delete all local data** clears history, damaged originals and the recovery preference without creating an old-state point. Unrelated files and deliberately exported backups remain separate.

For a journal-specific startup failure, a valid newest point enables **Restore and restart**. Quit remains the default; Open data folder still works. Before replacement, the exact damaged regular-file journal is retained as one local original (at most 64 MiB). **This raw original can contain saved memory and private text**, unlike ordinary memory-free checkpoints. A different existing original is never silently overwritten. Preserving it can temporarily use one additional raw-original staging file of at most 64 MiB, separate from permanent checkpoint limits. An interrupted raw stage blocks another preservation attempt until it is deliberately cleared, preventing repeated private staging copies. Clear history, character deletion and reset remove it; explicit saved-memory deletion/clear (the Clear button remains available for a chosen character even when the current memory list is empty) and external backup import also purge old originals and their managed crash temporaries. A purge failure refuses that privacy operation. Credentials and unrelated files are preserved. Safe restore refuses changed points, changed journals, oversized originals, linked files or failed preservation. Game observation may already be disconnected if a later journal write fails. If restart fails after restoration, close the app and reopen it manually. Credential faults and unrelated initialization faults do not offer journal restore.

Support reports include only recovery phase (`ready`, `unavailable`, `limit`), automatic choice and bounded point count. Point dates, IDs, paths and private journal text never enter a support report. Recovery is local protection, not a promise that a failing disk or an administrator modifying app files can be repaired automatically.

## Developer verification

Use synthetic local data only:

```powershell
node --test tests/diagnostics.test.cjs tests/diagnostics-ipc.test.cjs
npm run test:support
node --test --test-concurrency=1 tests/recovery-checkpoints.test.cjs tests/recovery-store.test.cjs tests/recovery-ipc.test.cjs tests/startup-recovery.test.cjs
npm run test:recovery
```

The Electron fixture uses isolated temporary data, fake native clipboard/dialog surfaces and synthetic canaries. It checks exact preview/copy/export equality, trusted requests, held controls/focus, layout and navigation/reset races without real player files, account sign-in, audio capture, inference or installers.
