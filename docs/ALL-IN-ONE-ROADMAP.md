# Backstage Forever All-in-One implementation roadmap

**Audit baseline:** `a73797cdf87449324b7cbc51408de688757eebb0`; release comparison: `v1.8.0` (`e498f82`). This is the execution plan, not a release announcement. “Exists” means present in audited source, not live-qualified or publicly shipped. The baseline includes post-tag encounter/quest/reputation awards, journal rollback and scan-order repairs, and reviewed Molten Core/Blackwing Lair tips. The opening Zul’Gurub work at `6833eba` is outside this baseline; reconcile that lane before editing the tip catalog. Keep the [historical roadmap](ROADMAP.md) as history. The initial Now/Compass implementation and release train have separate owners; do not edit those files on the roadmap branch or race them in follow-on work.

**Goal:** One optional companion for the full play loop: pick a character and an achievable goal, prepare, do the next step, see what actually happened, and pick up where you left off. The addon stands alone; saved-state desktop workflows work without live capture; the live link improves freshness where supported. Reuse Now, Adventure Compass, World Map, Ledger, Professions, Instance Atlas, Character Sheet, Badge Case, Journey and Companion, not a new dashboard for each feature. Default experience: one recommendation with a reason, a real next action, and a way to dismiss it. “All-in-One” does not mean parity with every addon.

## Sequenced delivery

Each slice gets a named owner at pickup (roles below define ownership boundaries, not assignments), a bounded worktree/branch, a failure-first test where behavior changes, and a receipt at its exact commit. Merge small vertical slices in dependency order. No routine approval pause for local implementation. When a human is unavailable, finish automated work with the capability safely gated, mark the corresponding live/permission gate **deferred**, and continue unaffected slices. Stop only the affected lane if proceeding would require unsupported data, a privacy change, credentialed deployment, or an unsafe migration.

## Evidence, safety and acceptance contract

- **Provenance:** show live public observation, last saved (age/time and toon), estimate, reference/community, or unknown distinctly. Resolve packs per profile and exact build; mismatched/unknown builds stay browse-only. Recheck character/view generation after awaits; clear on character switch, and test a late old response against the newly mounted target. Unknown is neither zero nor no quest/item/lockout. A public completion/player action event plus validated provenance can prove only its own fact: zone entry ≠ win, one boss ≠ clear or lockout, remembered loot ≠ personal drop, older turn-in ≠ repeatable completion. No timestamp fabrication.
- **Fair play:** guarded public game APIs only; no automation of movement, combat, quest acceptance, purchases, crafting, chat or reload; no protected-value dereference, combat bypass, executable Lua import, memory inspection, new game/network channel or desktop input. Preserve combat silence/failed-closed behavior and explicit user waypoints through existing native controls. The pixel link is one way. No new analytics or data-sharing defaults; no cloud-only dependency, credentials or paid service calls for core workflows.
- **Save and rollback:** replay actual addon modules in TOC order and dispatch registered events in Fengari. Export synthetic account and per-character files, load fresh VMs, then import through SavedVariables parser → profile merge → Store → reopen. Test partial data, dedup, stale callbacks after logout and budget pressure, and races between reputation/encounter rows. Preserve bounded export and parser budgets, original bytes on failed restore/migration, legacy IDs and prior backup behavior. Test actual `v1.8.0` Store after candidate startup alone, ordinary save and checkpoint; re-open candidate to check award durability. Old snapshot replacement can discard newer fields; document limits rather than promising general rollback across arbitrary restores. No production journal or addon writes in fixture validation.
- **Automated qualification:** run affected unit/IPC/renderer/Lua suites and generator checks on each slice. Check command changes against [command catalog test](../tests/commands-catalog.test.cjs); regenerate locales and run `check:locales`. Final integration uses [CI gate list](../.github/workflows/ci.yml), `npm test`, affected rendered commands, and `test:packaged` on the actual frozen build when packaging is authorized. Compare normal/minimum viewport screenshots on validated fixtures in English and compact German: empty/saved/live/disconnected, keyboard order and focus, reduced motion, missing art and same-title wrong-target cases. Inspect capture reports/errors, not just process exit. Save first-action visibility, not only page-fit screenshots.
- **Performance:** capture baseline and candidate with the same large synthetic roster, map/Atlas data, viewport, clock and idle machine. Record median and p95 selection/map/next-action latency, live decode/update delay and idle work, export bytes/parse budget, startup and asset sizes; add Lua counters for callbacks/rebuilds in combat and while idle/reloading. Agree numeric regression budgets against A0 before changing hot paths; do not raise existing byte/cap limits or claim FPS gains from fewer callbacks alone. Reuse existing schedulers and lazy detail queries, not another polling loop. Report native/performance physical checks separately from app fixture timings.
- **Release boundary:** use [releasing](RELEASING.md) and the actual [tag workflow](../.github/workflows/release.yml) rather than old README signing claims. Signed updater manifest and Authenticode are different checks. Authorized release owner verifies exact Windows executable/installer publisher/timestamp/version and uploaded hash, standalone addon, both Mac ZIPs, manifest and checksums; smoke clean install and the actual upgrade/rollback workflow in an isolated machine. No tags, uploads, deploys or changes to store credentials from this roadmap.
