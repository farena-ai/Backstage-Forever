# Backstage Forever 0.6.1

Repairs the character-selection and addon capture lifecycle problems found during live 0.6 use.

**[Download the Windows installer](https://github.com/farena-ai/Backstage-Forever/releases/download/v0.6.1/Backstage-Forever-0.6.1-Windows-x64-Setup.exe)**

## What changed

- A saved roster with no active selection now selects its first character consistently. A valid chosen character and the Follow my last played character preference stay intact. The dropdown and dashboard no longer disagree about whether a character is selected.
- The addon waits for login to restore its saved roster before capturing a character. Early loading events cannot replace the previous roster before it is read.
- Logout preserves the latest prepared snapshot instead of replacing valid XP, objectives and completion history with teardown-time API zeros. Events after logout cannot overwrite it; entering the world refreshes observations again.
- The 0.6 quest references, privacy boundaries and signed update verification remain in place.

## Activate the repair

Close BF and install normally, then reopen it. BF prepares the corrected addon in your connected game folder. In WoW, reload once to load the new addon, then reload again or log out to save a capture made with the repair. Visit the hunter and warrior once each and save after this update; older damaged snapshots need a new observation. Do not delete your characters or reset BF.

A character you have never visited while the addon is enabled cannot be discovered through this snapshot system. Login/capture is necessary once per character. Follow my last played character controls automatic selection; every captured character still stays in the roster when following is off.

## Verification boundary

Regression tests cover null selection, preserved deliberate selection, pre-login events, two-character roster restoration, logout/postlogout teardown and return to the world. Fixtures do not certify live-client behavior. The installer is not executed during automated acceptance; the player performs installation and reload. Updates remain authenticated with the pinned Ed25519 key; Windows Authenticode signing is separate and is not configured.
