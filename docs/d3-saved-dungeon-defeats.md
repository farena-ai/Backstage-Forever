# D3 first slice: saved dungeon defeats

**Base:** `61661872695423ac726973befde2525a5d6a4f34`. This slice adds a read-only panel to Characters → Journey. Badge Case keeps its existing award IDs, criteria and date behavior; both views now use the same qualifying encounter evidence.

- Source: the selected character’s validated addon save. The distinct count uses the instance map ID and encounter ID, not name, difficulty, repeat wins, reference data or another character. Only party encounters at or before the character’s export time qualify. Journey shows up to five recent recorded wins, preserving their original saved names and event times. It labels the save time separately. Missing evidence shows no count or date.
- Limits: the underlying history retains at most 100 observations; the count is not a lifetime total. Encounters carry no per-event build, so the panel neither labels defeats with the currently saved build nor joins to a build-specific catalog. There is no claim of a full run, lockout, ownership, loot, contribution, or clear. The local source audit found no existing exact lockout or client collection capture to reuse; no new API calls, schema, award, settings or telemetry are introduced.
- Verification: `tests/dungeon-encounters.test.cjs` covers TOC replay with toasts muted, parser → merge → Store → reopen, repeat/duplicate observations, distinct IDs, scoped and omitted history, future rows, failed and restricted events, and bounded display. `tests/rollback-journal.test.cjs` exercises the real v1.8.0 Store. `node scripts/badge-case-smoke.cjs [capture-directory]` exercises the real Electron UI in normal English and compact German, including a held Alpha Journey reply delivered after Beta renders. The captured renderer viewports were 1464×915 and 984×635 respectively.
- Deferred: live Forever client observation and installed upgrade/rollback. Quest-leg presentation and any combat estimate/readout changes are outside this first slice.
